TYPES OF CLOUD COMPUTING :
=========================

DEPLOYMENT MODEL ::
================

PUBLIC CLOUD – SERVICES SHARED BY MULTIPLE CUSTOMERS, MANAGED BY THIRD-PARTY PROVIDERS (E.G., AWS, AZURE).

PRIVATE CLOUD – DEDICATED TO A SINGLE ORGANIZATION WITH RESTRICTED ACCESS.

HYBRID CLOUD – MIX OF PUBLIC + PRIVATE CLOUD WITH DATA AND APPLICATION SHARING.

SERVICE MODEL ::
=============

IAAS (INFRASTRUCTURE AS A SERVICE) – VIRTUAL SERVERS, STORAGE, NETWORKING (E.G., AWS EC2, AZURE VM).

PAAS (PLATFORM AS A SERVICE) – READY PLATFORM WITH RUNTIME AND MIDDLEWARE TO DEPLOY APPLICATIONS (E.G., AWS ELASTIC BEANSTALK, GOOGLE APP ENGINE).

SAAS (SOFTWARE AS A SERVICE) – FULLY MANAGED APPLICATIONS DELIVERED OVER THE INTERNET (E.G., GMAIL, SALESFORCE).

=======================

        + NETWORK-----------|-----|-------|
	+ VIRTUALIZATION    |IAAS |	  |

	+ OS			  |       |SAAS

PUBLIC MODEL ::

IT CAN BE USED BY ANYONE PAY AS YOU GO MODEL AND MAINTAINCE CAN BE DONE IN 3RD PARTY SERVICES.
SHARED BY MULTIPLE USERS.

PRIVATE CLOUD ::
=============

A CLOUD WHICH IS RELATED TO PARTICULAR ORGINAZATION AND NO GENERAL PUBLIC ACCESS NOT BE PROVIDED.
ACCESS WILL BE RESTRICTED WHEN IT COMES TO PRIVATE CLOUD AN MAINTAINCE OF PRIVATE CLOUD WILL BE HANDS OF ORGANIZATION OF THIRD PARTY SERVICE.
DEDICATED TO ONE ORGANIZATION.
SECURE, CONTROLLED ACCESS.
COSTLY BUT SUITABLE FOR HIGHLY REGULATED INDUSTRIES. 

HYBRID CLOUD ::
============

IT HAS BOTH CHARACTER OF PUBLIC AND PRIVATE CLOUD WHERE A PRIVATE CLOUD ONLY ACTS AS A PUBLIC CLOUD FOR SOME
PERIOD OF TIME TO SOME DIFFERENT ORGANIZATION. IT DOESN'T NEED TO PAY FOR MAINTAINCE BUT THEY WILL PAY FOR USAGE OF CLOUD.
COMBINES PUBLIC + PRIVATE.
CAN SHIFT LOAD BETWEEN THEM (CLOUD BURSTING).
FLEXIBLE AND COST-EFFICIENT.

EBS(ELASTIC BLOCK STORE) ::
========================

EBS IS A BLOCK-LEVEL STORAGE SERVICE THAT PROVIDES PERSISTENT STORAGE VOLUMES FOR EC2 INSTANCES.

VOLUME ::
======

A VOLUME IS A VIRTUAL STORAGE DEVICE ATTACHED TO AN EC2 INSTANCE.
NOT PHYSICALLY PRESENT BUT BEHAVES LIKE A HARD DISK.
DEFAULT STORAGE: 8 GB FOR LINUX, 30 GB FOR WINDOWS.
PROVIDES BACKUP EVEN IF INSTANCE IS STOPPED OR TERMINATED.
VOLUMES ARE AVAILABILITY ZONE SPECIFIC.
CAN BE ATTACHED OR DETACHED FROM AN INSTANCE.

IMPORTANT QUESTION AMI CAN ALSO BACKUP THE DATA WHY WE WILL USE VOLUME FOR BACKUP THE DATA ::
==========================================================================================

AMI ::
===

NOT A PARALLEL STORAGE DEVICE.
USED FOR FULL BACKUP (SNAPSHOT OF OS + SOFTWARE).
NOT FLEXIBLE FOR FREQUENT CHANGES.

VOLUME ::
======

PROVIDES PARALLEL STORAGE.
CAN BE ATTACHED/DETACHED EASILY.
AVAILABILITY ZONE-SPECIFIC AND SCALABLE.
CAN STORE APPLICATION DATA SEPARATE FROM OS.

EBS STORAGE LIMITS & FEATURES ::
=================================

1 INSTANCE CAN BE ATTACHED TO MULTIPLE VOLUMES.
1 STANDARD VOLUME CAN ATTACH TO ONLY 1 INSTANCE AT A TIME.
EBS MULTI-ATTACH FEATURE → ALLOWS IO1/IO2 VOLUMES TO BE ATTACHED TO MULTIPLE INSTANCES.
MAX VOLUME SIZE → 16,384 GiB (16 TiB).

CONVERSION:
==========

1 GiB = 1,072 MB
1 GB = 1,024 MB

ROOT VOLUME ::
===========

THE MAIN VOLUME THAT CONTAINS THE OS.
CANNOT BE DETACHED WHILE THE INSTANCE IS RUNNING.
ROOT VOLUME CAN BE EXPANDED (E.G., 1 TiB MAY TAKE ~6 HOURS TO UPDATE).

TYPES OF VOLUME ::
===============

GENERAL PURPOSE PROCESSING --> SSD(GP3)
INPUT OUTPUT PROCESSING --> MAX : 16000 SPEED
THROUGHPUT(MIB/S) --> {MIN : 125 MIB, MAX : 1000 MIB, BASELINE : 125 MIB/S}
DATA FREQUENCY --> THE FLOW OF DATA

SIMPLE STORAGE SERVICE :: ( S3 )
================================

PROVIDES UNLIMITED OBJECT STORAGE.
STORES ANY TYPE OF DATA (IMAGES, VIDEOS, LOGS, BACKUPS, BIG DATA, ETC.).
USED FOR :-
TRANSFERRING ON-PREMISE DATA TO CLOUD.
STATIC WEBSITE HOSTING.
BIG DATA ANALYTICS (DATA LAKE, DATA WAREHOUSE).
MEDIA HOSTING, LIVE STREAMING.
EACH OBJECT MAX SIZE = 5 TB.
IN S3 WHAT WE STORE WILL BE CONSIDERED AS OBJECT
STORAGE SPACE RELATED TO S3 IS CALLED AS BUCKET . 
OBJECT/DATA CAN BE STORE IN S3 ONLY USING BUCKET.
S3 IS GOLOBAL SO ITS BUCKET NAME SHOULD BE UNIQUE GLOBALLY.
CAN BE USED WITH OR WITHOUT AN INSTANCE (SERVERLESS SERVICE).
DEFAULT BUCKET LIMIT = 100 BUCKETS PER ACCOUNT.
OBJECTS CAN BE ACCESSED USING S3 URL.

STORAGE CLASES OF S3 ::
==================== 

S3 STANDARD		→ DEFAULT CLASS (HIGH DURABILITY & AVAILABILITY).
S3 GLACIER		→ LOW-COST ARCHIVE STORAGE.
S3 GLACIER DEEP ARCHIVE	→ CHEAPEST STORAGE OPTION FOR LONG-TERM DATA.
S3 ONE ZONE-IA		→ INFREQUENT ACCESS, STORED IN SINGLE AZ (LOW COST, LESS REDUNDANCY).
S3 SNOWBALL 		→ PHYSICAL DEVICE FOR ON-PREMISE TO CLOUD DATA MIGRATION.
